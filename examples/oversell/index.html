Last Widget Co.

One shelf. Every tab at once.

A public AZX app — no login. The stock count lives at a single shared key that every visitor's tab reads and writes. Every purchase is a compare-and-swap: the write carries the version it read, and if someone else's write landed first, the platform answers 412 and the buyer transparently re-reads and retries. The bug this prevents is overselling — two tabs buying the same last widget, both told "yours."

The waitlist — a shared namespace that grows at runtime (ADR-0042)

Each join creates record:<id> under a prefix grant — no manifest edit per record. The index view below is one list call (GET /_api/data/shared?prefix=record:): the app keeps no record-index key of its own, so there is no index to lose a write race on.

    Try to break it: the two-tab oversell

    Open this page in a second tab. Restock to 1, then press Buy one in both tabs. One tab wins. The other gets a 412, re-reads, and sees an empty shelf — instead of selling a widget that no longer exists. Watch the exchange log below: the losing tab's retry is the whole feature.

        Probes: prefix grants & the list verb (ADR-0042)
        
    
          A prefix grant authorizes every key that starts with it — unboundedly many, chosen
          by the app at runtime, which is why the grant needs admin approval. The list verb ships
          with it: without a list, a growing namespace forces the app to maintain its own index key.
          These probes drive the boundaries.
