# Local development

Everything runs locally with no Azure account. The dev environment is a
container (VS Code: _Reopen in Container_) with Node 24, pnpm, Postgres, and
Azurite (Blob emulation) wired up.

## The services

Each runs as its own process, from its own command:

| Command | Service | Port |
| --- | --- | --- |
| `pnpm dev:edge` | helix-edge — serves apps, sign-in, the gateway | 8080 (https) |
| `pnpm dev:portal` | helix-portal — control plane, deploy API | 3001 |
| `pnpm dev:web` | portal SPA dev server (proxies to :3001) | 5173 |
| `pnpm dev:idp` | local OIDC issuer standing in for Entra | 3002 |
| `pnpm dev:egress` | helix-egress — the outbound fetch proxy | 8081 |
| `pnpm dev:docs` | this docs site | — |

Locally, apps live on `https://<slug>.local.helix.azxlabs.io:8080` and sign-in
on `auth.local.helix.azxlabs.io`. TLS certificates are generated by mkcert on
first setup, so the browser is happy without warnings.

The local IdP replaces Entra with fixture users and clients. The flow is the
same as production — production only swaps the issuer for your tenant's.

## Testing against a real Entra tenant

Before the Azure deploy you can point local services at a real tenant. Add the
local redirect URIs to the app registrations
([Entra setup](/deploy/entra-setup)), then drop an `apps/edge/.env.local`
(git-ignored) with the issuer and client values, and restart the edge. Details
in [the runbook](https://github.com/AZX-PBC-OSS/helix/blob/main/docs/runbooks/entra-app-registration.md#local-testing-against-real-entra).
Delete the file to go back to the local IdP.

## Checks

```bash
./check-and-lint.sh          # typecheck, lint, format, tests — the CI gate
pnpm --filter @azx-pbc/portal db:migrate   # create/apply a Prisma migration
```

Tests run against the local Postgres and Azurite services; the suite sets
itself up. Two projects run: plain node tests for every backend package, and a
browser-environment suite for the portal SPA.

## Deploying an app locally

Use the CLI from an app directory against the local portal, or run the platform
and click through the portal UI at :5173. The
[CLI page](/apps/cli) has the commands; the only local difference is the portal
URL (`http://localhost:3001`, the CLI's default).
